# 验收标准

## Bug 修复要求

必须解决以下所有安全问题：

1. **SQL 注入**：输入 `' OR '1'='1` 不能绕过登录验证
2. **参数化查询**：必须使用 `?` 占位符加参数数组的方式
3. **输入验证**：username 和 password 必须是字符串类型，拒绝数组/对象等非法类型
4. **密码哈希**：不能明文存储和查询密码，应使用 bcrypt 对比哈希值

## 验收条件

### 安全测试

以下注入尝试必须全部失败（返回 401 而非 200）：

```bash
# SQL 注入 - 恒真
curl -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin", "password":"' OR '1'='1"}'

# SQL 注入 - 注释绕过
curl -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin' --", "password":"anything"}'

# SQL 注入 - 联合查询
curl -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin", "password":"' UNION SELECT * FROM users--"}'
```

### 类型验证

```bash
# 传入非字符串类型应返回 400
curl -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{"username":[], "password":"test"}'
```

## 测试命令

```bash
# 检查代码中是否仍有字符串拼接的 SQL
grep -n "SELECT.*\`\$\{" login.js && echo "仍有注入风险！" || echo "已使用参数化查询"

# 运行安全测试
node --test security.test.js
```
