# 验收标准

## Bug 修复要求

修复后必须解决以下所有问题：

### 问题 1：socket 事件监听器泄漏
- `addUser` 中添加的 `message`、`disconnect`、`typing` 监听器应在适当时机移除
- 使用 `once()` 替代 `on()` 处理 `disconnect` 事件（断开后不需要再监听）
- 在 `removeUser` 中清理 socket 上的所有监听器

### 问题 2：room-message 监听器泄漏
- `joinRoom` 中添加的 `room-message` 监听器应在 `leaveRoom` 中移除
- 使用具名函数或 Symbol 作为监听器引用，方便移除
- 离开房间或用户断开时清理房间级别监听器

### 问题 3：全局监听器管理
- `setupGlobalHandlers` 应返回移除函数，便于清理
- 服务器关闭时移除所有已注册的全局监听器

### 问题 4：轮询服务泄漏
- `createPollingService` 中的 `once('stats')` 应只注册一次，而非每次轮询都注册

### 通用要求
1. 事件监听器的添加和移除必须成对出现
2. 使用 `EventEmitter` 的 `listenerCount` 或 `eventNames()` 监控监听器数量
3. 关键路径上添加 `setMaxListeners` 防止误报（但这不是修复泄漏的借口）
4. 不再需要的监听器必须被垃圾回收

## 验收条件

1. **监听器零增长**：模拟 100 个用户连接/断开后，`server.listenerCount('room-message')` 应归零
2. **socket 可 GC**：用户断开后，socket 对象不应被任何事件监听器引用
3. **全局监听器可移除**：调用清理函数后，全局监听器被移除
4. **轮询不累积**：`stats` 的事件的监听器数量在 100 秒轮询后应为 1（而非 100）
5. **server 关闭后**：所有监听器被清理，EventEmitter 可被 GC
