# 验收标准

## 功能正确性

1. 基本 get/put：`put(1,1)` 后 `get(1)` 返回 1
2. 频率淘汰：容量 2，put 三个 key，频率最低的被淘汰
3. 频率相同淘汰最久未使用：两个 key 频率相同，淘汰更久未使用的
4. get 增加频率：多次 get 同一个 key 增加频率，避免被淘汰
5. put 更新已有 key：更新 value 并增加频率，不增加条目数
6. 容量为 1 的场景：每次 put 新的就淘汰旧的
7. 大规模操作：1000 次 put + get 无报错

## 性能要求

- get 和 put 必须都是 O(1) 时间复杂度
- 必须使用**哈希表 + 频率链表（嵌套双向链表）** 结构
- 不能通过遍历计算频率
- 不能使用 Map 的插入顺序特性投机

## 实现要求

- 需要维护：key->value 映射、key->频率 映射、频率->对应 key 链表 映射
- 跟踪当前最小频率 `minFreq`
- 频率相同时按 LRU 淘汰
