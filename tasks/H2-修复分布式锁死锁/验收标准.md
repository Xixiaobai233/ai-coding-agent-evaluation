# 验收标准

## Bug 修复要求

必须解决以下所有问题：

### 问题 1：误删别人的锁
当前 Unlock 直接 `Del`，不检查 value。如果锁已经过期被其他实例获取，当前实例的 Unlock 会删除别人的锁。
**修复**：用 Lua 脚本确保只删除自己的锁（比较 value 后再 Del）。

### 问题 2：锁没有续期
业务执行时间可能超过 TTL，导致锁提前过期，多个实例同时处理同一任务。
**修复**：启动一个后台 goroutine 定时续期（看门狗模式），业务完成后停止续期。

### 问题 3：Panic 安全
虽然用了 `defer`，但如果没有解决"误删别人的锁"的问题，panic 时反而会制造更多问题。
**修复**：确保 Unlock 是幂等的、安全的。

## 验收条件

1. **锁互斥**：两个 goroutine 同时 Lock，只有一个成功
2. **锁安全释放**：成功获取锁的 goroutine 释放后，另一个能获取到
3. **不误删锁**：锁过期后其他实例获取了锁，原实例 Unlock 不会误删
4. **续期机制**：业务执行时间超过 TTL 时锁不会提前过期
5. **Panic 安全**：加锁后的业务代码 panic，锁最终能正确释放
6. ** Lua 脚本**：使用 Lua 保证解锁操作的原子性
