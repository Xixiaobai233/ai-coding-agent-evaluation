# 验收标准

## 压力测试要求

### 测试 1：高吞吐

- 100 个 goroutine 并发提交，总共提交 10000 个任务
- 每个任务是一个简单的计数器递增
- 所有任务必须被执行完毕（最终计数器 = 10000）
- 测试应在 5 秒内完成

### 测试 2：背压

- 创建一个容量很小的队列（例如容量 10，worker 1 个）
- 快速提交大量任务
- 验证 `Submit` 有时返回 false（队列满时）
- 验证 `SubmitWithContext` 在超时后返回 error

### 测试 3：优雅关闭

- 提交一批任务，然后调用 `Shutdown`
- Shutdown 返回后：
  - 所有已提交的任务必须已完成
  - 调用 `Submit` 可能 panic 或返回 false（取决于设计）
  - 没有 goroutine 泄漏（`runtime.NumGoroutine` 检查）

### 测试 4：并发安全

- 用 `-race` flag 运行测试，不能有 data race 警告
- 同时在多个 goroutine 中调用 `ActiveCount`

## 测试命令

```bash
go test -race -v -count=1 -timeout=30s ./...
go test -bench=. -benchmem ./...
```
