# 验收标准

## Bug 修复要求

修复方案必须满足以下条件：

1. **不再 panic**：1000 个 goroutine 并发读写不会崩溃
2. **性能优先**：读多写少场景下推荐使用 `sync.RWMutex`，读操作用 `RLock()`，写操作用 `Lock()`
3. **不能使用 `sync.Map` 蒙混过关**：需要手写并发控制，展示对并发原语的理解

## 验收条件

1. 并发 100 个 goroutine 同时读写 map，程序正常结束（不 panic）
2. 并发 1000 个 goroutine 同时只读 map，性能良好（没有锁竞争导致的严重阻塞）
3. Get/Set/Delete 方法签名保持不变
4. 数据一致性：读取到的 value 和写入的 value 匹配

## 测试命令

```bash
go run main.go
go test -race -v -count=1 ./...  # 用 race detector 验证
```
