# 验收标准

## 重构要求

### 必须定义的微服务接口

1. **`IOrderService`** — 创建订单、查询订单、取消订单
2. **`IPaymentService`** — charge(支付扣款)、refund(退款)
3. **`IInventoryService`** — reserve(预留库存)、release(释放库存)
4. **`IShippingService`** — createShipment(创建运单)、cancelShipment(取消运单)
5. **`INotificationService`** — sendEmail、sendSMS

### Saga 模式要求

重构后的 `createOrder` 必须：

1. **正向流程**：
   - InventoryService.reserve → PaymentService.charge → OrderService.create → ShippingService.createShipment → NotificationService.send

2. **补偿事务（Saga）**：
   - 库存预留失败 → 直接返回错误
   - 支付失败 → 释放库存预留
   - 订单创建失败 → 退款 + 释放库存
   - 物流创建失败 → 标记订单需人工干预（不撤销支付和库存）

3. **幂等性考虑**：每个接口考虑 `idempotencyKey`

### 代码质量

- 所有 service 定义在独立的 TypeScript 文件中
- 使用明确的类型定义（DTO/VO）
- 错误处理使用自定义错误类型（区分业务错误和系统错误）
- 有单元测试验证 Saga 编排逻辑
