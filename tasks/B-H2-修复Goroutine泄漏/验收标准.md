# 验收标准

## Bug 修复要求

修复后必须解决以下所有问题：

### 问题 1：DataProcessor goroutine 泄漏
- `inputChan` 关闭时，worker goroutine 应优雅退出
- 使用 `value, ok := <-inputChan` 检测 channel 关闭，或使用 `range` 循环
- 添加 `Close()` 或 `Shutdown()` 方法

### 问题 2：HealthChecker 无法停止
- `Start` 应监听 `stopChan`，收到信号后退出 goroutine
- `Stop` 正确通知 goroutine 退出
- `time.Ticker` 在 goroutine 退出时应被 `Stop()` 释放

### 问题 3：FanOutService 无生命周期管理
- 添加 `Shutdown()` 方法，关闭所有 worker channel 并等待 goroutine 退出
- 使用 `sync.WaitGroup` 跟踪所有 worker goroutine

### 问题 4：EventBroadcaster 阻塞
- `Broadcast` 方法在 listener 满时不应阻塞
- 添加 `default` 分支，丢弃无法发送的事件（或使用带超时的发送）

### 通用要求
1. 所有启动的 goroutine 都必须有明确的退出路径
2. 主程序退出前应等待所有 goroutine 结束
3. 使用 `sync.WaitGroup` 跟踪 goroutine 生命周期
4. 优先使用 `context.Context` 传递取消信号

## 验收条件

1. **可停止的 DataProcessor**：调用 `Close()` 后，内部 goroutine 在 1 秒内退出
2. **可停止的 HealthChecker**：调用 `Stop()` 后，goroutine 退出，ticker 释放
3. **可关闭的 FanOutService**：调用 `Shutdown()` 后等待所有 worker 完成，不泄漏
4. **非阻塞广播**：`Broadcast` 在 listener 满时不会阻塞调用方
5. **goroutine 计数**：所有服务停止后，程序不应残留 goroutine（除 runtime 内部 goroutine 外）

## 测试命令

```bash
go test -race -v -count=1 ./...
# goroutine 泄漏检测
go test -v -count=1 -run TestNoLeak ./...
```
